# Engineering-core v0.8.0 local release

## Title

Engineering-core v0.8.0 — deterministic owner-use work packets and evidence bundles

## Release body

v0.8.0 connects the existing deterministic plan compiler, bounded provider-neutral advisor, owner dispositions/receipts, and repository drift checks through three explicit commands:

- `prepare-work`
- `finalize-work`
- `verify-work`

The workflow starts from owner-supplied task context and one explicit repository mapping. It binds full Git revision, focused no-follow file snapshots, repository facts, plan, optional advisor request, external advice, owner decisions, and owner receipt claims without executing commands, invoking models, applying patches, or promoting authority.

### Breaking Changes

No existing JSON schema identifier changed, but input handling is intentionally stricter: advisor and closed-loop inputs that rely on symlinks, duplicate JSON members, non-finite numbers, malformed citations/patches, or special files are now rejected. These inputs were never safe evidence. Running the v0.8 package against a repository still pinned to `v0.7.0` also reports the expected `released-mismatch` until that repository deliberately upgrades.

### Agent migration notes

Well-formed v0.7 inputs require no schema migration. Remove unsafe path indirection or malformed JSON if the new bounded loader rejects an old local artifact. Agents that opt into the workflow should construct `engineering-work-context-v1` from the owning task surface, write CLI stdout only to an owner-approved location, and keep AK or the declared owner authoritative. `verify-work` returning `matched` is not an execution, CI, release, compliance, or approval claim.
