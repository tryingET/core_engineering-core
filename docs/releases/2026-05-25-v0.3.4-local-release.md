# Local release draft — engineering-core v0.3.4

## Title

`engineering-core v0.3.4 — repo loop validation contract visibility`

## Release body

This patch release adds `repo-loop-validation-v1`, a repo-owned command contract for agent, slash-command, visible-loop, nexus-loop, and future prompt-loop validation phases.

Engineering-core provides the reusable vocabulary, templates, and scanner visibility. Repos still own command semantics, local validation evidence, AK/task/decision boundaries, landing gates, and release or production authority.

### Breaking Changes

- None.

### Added

- `repo-loop-validation` template retrievable with `engineering-core show-template repo-loop-validation`.
- Optional `engineering_core.loop_validation` policy declaration for `repo-loop-validation-v1` command coverage.
- `scan-adoption` loop-validation fields and summary counts:
  - `has_loop_validation_contract`
  - `loop_validation_version`
  - `loop_validation_status`
  - `loop_validation_commands`
  - `loop_validation_missing_commands`
  - `loop_validation_notes`
- Markdown scan rendering for loop validation status.
- Optional repo-loop-validation sections in engineering-local and validation-tier-map templates.

### Changed

- Validation and testing disciplines now explain loop validation as evidence-producing repo guidance, not authority.
- Adoption docs and authority map clarify that loop validation visibility is optional and repo-owned.
- README and vision mention optional loop-validation scanner visibility.
- Bumped package/catalog metadata to `0.3.4`.

### Fixed

- None.

### Agent migration notes

- Repos that want loop validation visibility should declare `engineering_core.loop_validation.version = "repo-loop-validation-v1"` and map all six phase commands or explicit `n/a:` fallbacks.
- `absent` loop validation does not make an engineering-core adoption record partial.
- `partial`, `invalid`, or `unknown-version` loop validation means only that a declared optional contract needs review.
- Loop command success should be reported as evidence, not as merge approval, AK task closure, semantic completion, release approval, or production activation.
