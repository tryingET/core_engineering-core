# Local release draft — engineering-core v0.7.0

## Title

`engineering-core v0.7.0 — explicit owner-evidence reconciliation`

## Release body

This release adds a separate, explicit reconciliation surface for owner-produced planning and advice receipts. It joins exact repository identities, bounded no-follow artifacts, current deterministic plan bindings, recommendation identity, and Git revision ancestry without changing doctor or capability-scan authority.

Engineering-core continues to execute no consumer-declared command, invoke no external model, apply no patch, mutate no consumer repository, authenticate no owner, and promote no CI/release/AK/compliance or rollout authority.

### Breaking Changes

- None to existing doctor, scan-capabilities, planning, advice, or closed-loop schemas. Record-file ingestion now rejects symlinks, symlinked parents, FIFO/special files, oversized inputs before reading, invalid UTF-8 JSON, and read races.

### Added

- `engineering-core reconcile-evidence --repo <id> <path> --receipt <file>`.
- `engineering-evidence-reconciliation-v1` matched/stale/mismatched projections.
- Explicit repository identity mapping, exact receipt owner/target joins, and digest-selected v0.6 catalog compatibility snapshots.
- Planning self-digest and bounded advice-request/recommendation validation.
- Fixed Git revision probes with current, advanced-compatible, stale, and mismatched relations.
- Shared bounded no-follow regular-file input primitives.
- Deterministic evidence-reconciliation dogfood and adversarial tests.

### Changed

- Bumped package and both catalog versions to `0.7.0`.
- Hardened existing receipt/disposition/calibration/pattern input loading.
- Extended local release verification and artifact inspection for reconciliation modules and dogfood.

### Agent migration notes

- Keep using `doctor` and `scan-capabilities` for receipt-free static observation.
- Use `reconcile-evidence` only with explicit repository-id/path mappings and explicit receipt paths.
- Treat matched owner states as supplied owner claims, not authenticated or independently verified evidence.
- Do not discover receipts, open observation URLs, or execute observation references.
- Preserve `schema-valid` when that is the receipt state; never rewrite it as execution-observed or evidence-verified.
