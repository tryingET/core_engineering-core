# Local release draft — engineering-core v0.5.0

## Title

`engineering-core v0.5.0 — bounded planning and closed-loop evidence`

## Release body

This release adds deterministic advisory planning, provider-neutral advice validation, owner-bound dispositions and receipts, calibration, multi-input pattern synthesis, and unapplied doctrine proposals. It also makes adoption scanning explicitly bounded and reports incomplete traversal truthfully.

Engineering-core remains read-only: it does not execute consumer commands, apply patches, promote CI/release/AK/compliance truth, or self-authorize doctrine.

### Breaking Changes

- None to the supported `engineering-core` CLI. No legacy `tech-stack-core` aliases are restored.

### Added

- `plan`, `explain`, and `advise` command surfaces with deterministic, digest-bound evidence.
- Receipt, disposition, calibration, pattern, and doctrine-proposal contracts and CLI commands.
- Reproducible `scripts/dogfood-closed-loop.py` closure harness.
- Typed catalog, policy, and repository-fact validation.
- Explicit scanner traversal/read budgets, omissions, failures, and completeness reporting.

### Changed

- Bumped package and both catalog versions to `0.5.0`.
- Strengthened release verification and artifact inspection.

### Fixed

- Secret-bearing JSON key/value records now fail closed.
- Unsafe/hallucinated patch paths, unknown IDs, malformed records, and provenance mismatches fail closed.

### Agent migration notes

- Treat plans, advice, receipts, calibration, patterns, and proposals as advisory projections only.
- Consumer owners retain command execution and evidence authority; doctrine owners retain proposal acceptance authority.

```bash
python scripts/release-local.py verify --version 0.5.0

```
