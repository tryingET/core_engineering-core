# engineering-core v0.12.2

## Title

engineering-core v0.12.2 — `engineering-core pin` moves a release pin and nothing else

## Release body

v0.12.1 fixed `migrate --ref`, but moving a pin with `migrate` still didn't work on real repos. It refused every hand-written `docs/engineering.local.md`, `--force` replaced that file with the managed template, and the policy was re-rendered with sorted keys. The v0.12.1 reconcile round (AK6102–AK6117) therefore moved pins by hand again.

The new `engineering-core pin --ref <tag> --ref-commit <sha>` edits only the pin:

- In `policy/engineering-lane.json`: `ref`, `release_pin`, `repository`, and the `--from` source of every engineering-core command (quoting kept). Key order, formatting and all other keys stay as they were.
- In `docs/engineering.local.md`: the same sources, and the old commit and old tag on the release-pin line. Other text, including history like "Up to v0.12.0 …", is untouched.
- A `ref` that is a raw 40-character commit keeps that shape. A `git+file` or checkout-path source becomes the portable GitHub source.
- If an old pin value is also used by an unrelated key, the plan refuses with a conflict.
- It's a dry run until `--apply`, and it writes no adoption journal.

A dry run over all 205 workspace policies produced 196 clean pin-only diffs, 9 already current, and no conflicts (AK6101).

### Breaking Changes

None. `init`, `migrate`, `rollback` and `remove` are unchanged.

### Verification before tag

Run from the repository root with full Git history and tags available:

```bash
uv sync --locked
uv run python -m unittest discover -s tests
uv run python -m engineering_core.self_check --repo-root .
uv run python scripts/check-release-lineage.py --mode ci
uv run python scripts/check-justfile-addenda.py
uv run python scripts/sync-skill-assets.py --check
uv run python scripts/lane-conformance.py --all
uv run python scripts/release-local.py verify --version 0.12.2
uv build
```

CI runs the same verify on `ubuntu-24.04` before the auto-release workflow tags `v0.12.2` on the exact CI-validated commit.

### Agent migration notes

No Agent Kernel state changes are required. To move a repo to this release:

```bash
git ls-remote https://github.com/tryingET/core_engineering-core.git 'refs/tags/v0.12.2^{}'
uv tool -n run --from 'git+https://github.com/tryingET/core_engineering-core.git@<sha>' engineering-core pin --repo . --ref v0.12.2 --ref-commit <sha>
uv tool -n run --from 'git+https://github.com/tryingET/core_engineering-core.git@<sha>' engineering-core pin --repo . --ref v0.12.2 --ref-commit <sha> --apply
```

engineering-core's own self-adoption pin advances after this release is published.
