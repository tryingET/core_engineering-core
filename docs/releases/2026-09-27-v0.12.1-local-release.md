# engineering-core v0.12.1

## Title

engineering-core v0.12.1 — `migrate --ref` moves the whole release pin

## Release body

A patch release with one fix. In v0.12.0 and earlier, `engineering-core init`/`migrate --ref <tag>` kept a repository's existing pin: the old `ref` won, and `release_pin` and the pinned commands were never touched (`migrate --ref v0.12.0` on a v0.7.0 repo changed nothing but key order). The v0.12.0 fleet rollout (AK6050–AK6054) moved every pin by hand for that reason.

Now an explicit `--ref` together with the new `--ref-commit <sha>` moves `ref`, `release_pin`, `repository` and every pinned command to the portable GitHub source in one step. If the repository is pinned and `--ref-commit` is missing, the command refuses with a conflict that names the `git ls-remote` command yielding the commit. Without `--ref`, the existing pin is kept as before (AK6055).

The rollout itself surfaced no other engineering-core defect. Its recorded consumer deviations (TypeScript 5 kept by tools that use the classic compiler API; no Typst or Kotlin lane) are consumer adoption decisions or feature requests, not fixes for this release.

### Breaking Changes

None. `--ref` no longer has a default value; callers that passed it explicitly are unaffected.

### Verification before tag

Run from the repository root with full Git history and tags available:

```bash
uv sync --locked
uv run python -m unittest discover -s tests
uv run python -m engineering_core.self_check --repo-root .
uv run python scripts/check-release-lineage.py --mode ci
uv run python scripts/check-justfile-addenda.py
uv run python scripts/sync-skill-assets.py --check
uv run python scripts/lane-conformance.py --all
uv run python scripts/release-local.py verify --version 0.12.1
uv build
```

CI runs the same verify on `ubuntu-24.04` before the auto-release workflow tags `v0.12.1` on the exact CI-validated commit.

### Agent migration notes

No Agent Kernel state changes are required. Consumers on v0.12.0 need to move only if they use `engineering-core migrate` to change pins. To move a pin with this release:

```bash
git ls-remote https://github.com/tryingET/core_engineering-core.git 'refs/tags/v0.12.1^{}'
engineering-core migrate --repo . --ref v0.12.1 --ref-commit <sha from above>
```

engineering-core's own self-adoption pin advances after this release is published.
