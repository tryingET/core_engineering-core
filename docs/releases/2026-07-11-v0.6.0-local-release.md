# Local release draft — engineering-core v0.6.0

## Title

`engineering-core v0.6.0 — factual capability observation`

## Release body

This release turns capability-readiness snippets into stable package-native commands. It adds an exact optional capability declaration, a deterministic non-executing repository doctor, and explicit-population capability scanning without claiming canonical society inventory or execution evidence.

Engineering-core continues to execute no consumer commands, invoke no external model, apply no patches, mutate no consumer repository, and promote no CI/release/AK/compliance authority.

### Breaking Changes

- None to existing CLI and policy contracts. Older v0.5 catalogs remain parseable; the optional v0.6 capability contract is additive.

### Added

- `engineering-core-capabilities-v1` declaration parsing.
- `engineering-core doctor --repo ...` with declaration, static-observation, and evidence dimensions.
- `engineering-core scan-capabilities --repo/--repo-file` over explicit owner-produced populations.
- Bounded no-follow repository-file ingestion and exact report schemas.
- `scripts/dogfood-capabilities.py` with deterministic, negative-path, exit-code, non-execution, and non-mutation probes.
- RFC, ADR, review, implementation, validation, rollout, and rollback artifacts linked to AK decision 51.

### Changed

- Bumped package and both catalog versions to `0.6.0`.
- Added typed closed-loop protocol identifiers while retaining v0.5 catalog compatibility.
- Extended release verification and source artifact inspection for capability modules and dogfood.

### Agent migration notes

- Do not call static capability observations `adopted` or `verified`.
- Supply repository populations explicitly from an owner-approved inventory.
- Capability declarations contain no executable command fields.
- Runtime evidence and rollout closure remain with repository owners and AK where accepted.
