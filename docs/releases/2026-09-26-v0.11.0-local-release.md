# engineering-core v0.11.0

## Title

engineering-core v0.11.0 — executable lanes: every lane's config and gates proven at release

## Release body

Lane docs embedded configuration that repos copy verbatim, but nothing ever executed it. An audit of every lane against the real tools found silent false passes everywhere: gates that pass on failures and settings tools silently ignore. This release fixes them and adds `scripts/lane-conformance.py`, which runs each lane's own **Quality gates** on a fixture with pinned tools, requires every gate to reject a must-fail probe, and builds and runs the lanes' Dockerfiles. Release verify runs it for all seven lanes, so a lane can no longer ship config that doesn't work. See `CHANGELOG.md` for the per-lane list and `docs/project/2026-09-23-lane-config-conformance-greats.md` for the design and refutations.

Also in this release: TypeScript 7-only ts and pi-ts lanes, a machine-independent `uv.lock` (with a release guard), hardened G4-B verification, and spec-valid projected skill names.

### Breaking Changes

- **Python 3.13+** is required to install engineering-core (was 3.10+).
- **Skill names:** the 15 lane-addendum skills are renamed to Agent Skills spec names (dots become hyphens, e.g. `ec-lane-ts.justfile` -> `ec-lane-ts-justfile`). Dotted **profile** names keep resolving as `deprecated_aliases` through 0.11.x; switch to the hyphenated names. Agents that name a dotted *skill* directly must update. The live fleet uses `ec-full` and is unaffected.
- **ts / pi-ts lanes:** TypeScript 7 only. Replace `@typescript/native-preview` with exactly pinned `typescript@7` and `tsgo --noEmit` with `tsc --noEmit`; drop `typecheck:fallback`. Replace dev tools that need the classic compiler API instead of keeping TypeScript 6; runtime use of that API must be a dependency under an explicit package name.
- **Lane config changes consumers should adopt** when they bump their `release_pin`: Biome 2.x config shape (`biome migrate --write`), `bunfig.toml` instead of `bun.toml`, `rust-toolchain.toml` pin and `--workspace --locked` cargo gates, the py lane's `[tool.uv] exclude-newer = "7 days"` (repos whose lock records the span without it fail `--locked` in clean environments; see AK5998).

### Verification before tag

Run from the repository root with full Git history and tags available:

```bash
uv sync --locked
uv run python -m unittest discover -s tests
uv run python -m engineering_core.self_check --repo-root .
uv run python scripts/check-release-lineage.py --mode ci
uv run python scripts/check-justfile-addenda.py
uv run python scripts/sync-skill-assets.py --check
uv run python scripts/lane-conformance.py --all
uv run python scripts/release-local.py verify --version 0.11.0
uv build
```

`lane-conformance.py --all` needs the lane base toolchains (bun, docker, cargo/rustup, go, uv, a C++ compiler, mix/elixir, sbcl); CI installs them via `.github/actions/lane-toolchains`. CI runs the same verify before the auto-release workflow tags `v0.11.0` on the exact CI-validated commit.

### Agent migration notes

No Agent Kernel state changes are required. Consumers adopt through their `policy/engineering-lane.json` `release_pin`; the lane changes above apply when a repo moves its pin to `v0.11.0`. engineering-core's own self-adoption pin advances after this release is published.
