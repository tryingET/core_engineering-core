# engineering-core v0.12.0

## Title

engineering-core v0.12.0 — machine-independent locks, quarantine ownership rule, pinned CI runner

## Release body

This release finishes the cleanup that v0.11.0 started. The one-release profile aliases for the old dotted lane-addendum names are removed. `scan-adoption` can now detect the machine-dependent `uv.lock` defect that affected 13 workspace repositories (including engineering-core itself), so the next occurrence is caught automatically instead of by hand. The `dependency-governance` discipline gains a rule for giving your own packages a green light from release-age quarantines without letting a stranger's same-named package through. CI now runs on a pinned Ubuntu 24.04 image with current Node 24 actions.

### Breaking Changes

- **Profile aliases removed.** Replace any dotted lane-addendum profile name with its hyphenated form:

  | Removed | Use |
  |---|---|
  | `ec-ts.justfile` | `ec-ts-justfile` |
  | `ec-ts.frontend` | `ec-ts-frontend` |
  | `ec-ts.ts-quality` | `ec-ts-ts-quality` |
  | `ec-ts.evidence-safety` | `ec-ts-evidence-safety` |
  | `ec-ts.ultracite-pilot` | `ec-ts-ultracite-pilot` |
  | `ec-pi-ts.justfile` | `ec-pi-ts-justfile` |
  | `ec-pi-ts.ts-quality` | `ec-pi-ts-ts-quality` |
  | `ec-py.justfile` | `ec-py-justfile` |
  | `ec-go.justfile` | `ec-go-justfile` |
  | `ec-rust.justfile` | `ec-rust-justfile` |
  | `ec-rust.build-graph` | `ec-rust-build-graph` |
  | `ec-cpp.justfile` | `ec-cpp-justfile` |
  | `ec-cpp.cuda` | `ec-cpp-cuda` |
  | `ec-elixir.justfile` | `ec-elixir-justfile` |
  | `ec-common-lisp.justfile` | `ec-common-lisp-justfile` |

  The rule is mechanical: replace the dot with a hyphen. `ec-full` and all base-lane profiles are unchanged. At release time no agent in the fleet and no file in the workspace used a dotted name (`build_skill_projection.py --check --fleet-root` passes).
- Everything breaking in v0.11.0 (Python 3.13+, renamed skills, TypeScript 7-only ts lanes) still applies; consumers moving from v0.10.0 should read the v0.11.0 notes first.

### Verification before tag

Run from the repository root with full Git history and tags available:

```bash
uv sync --locked
uv run python -m unittest discover -s tests
uv run python -m engineering_core.self_check --repo-root .
uv run python scripts/check-release-lineage.py --mode ci
uv run python scripts/check-justfile-addenda.py
uv run python scripts/sync-skill-assets.py --check
python3 scripts/build_skill_projection.py --check --fleet-root ~/ai-society/agents
uv run python scripts/lane-conformance.py --all
uv run python scripts/release-local.py verify --version 0.12.0
uv build
```

CI runs the same verify on `ubuntu-24.04` before the auto-release workflow tags `v0.12.0` on the exact CI-validated commit.

### Agent migration notes

No Agent Kernel state changes are required. Consumers adopt by moving their `policy/engineering-lane.json` `release_pin` to `v0.12.0` and renaming any dotted profile names. Python repositories should also run `engineering-core scan-adoption` and fix any `uv_lock_records_undeclared_setting` flag by declaring the setting under `[tool.uv]` and relocking. engineering-core's own self-adoption pin advances after this release is published.
